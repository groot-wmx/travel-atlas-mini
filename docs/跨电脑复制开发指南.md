# 旅图小程序：跨电脑复制与开发指南

更新日期：2026年9月2日

本文用于把「旅图」项目复制到另一台电脑，并继续开发网页预览版和微信小程序版。按照本文操作，不需要复制原电脑上的 `node_modules`、构建产物或微信上传密钥。

## 1. 项目现状

旅图目前是一套可以运行的旅行社区产品初稿，核心方向包括：

- 发现国内和全球景点；
- 查看景点介绍与旅行者景评；
- 收藏想去、标记去过；
- 使用日历形式规划旅行；
- 发布旅行攻略、照片和景评；
- 通过「旅圈」交流城市、路线和旅行方式。

当前版本采用 Mock 数据和本地存储，适合验证页面、产品结构和交互。

目前尚未接入：

- 用户账号与微信登录；
- 云端数据库；
- 真实图片上传；
- 攻略、景评和旅圈内容发布接口；
- 内容审核与举报；
- 消息通知；
- 管理后台。

因此，复制到新电脑后可以继续开发和演示，但不同设备之间的数据不会同步。

## 4. 从原电脑复制哪些内容

复制整个 `travel-atlas-mini` 文件夹，但不要复制以下内容：

```text
node_modules/
dist/
dist-h5/
artifacts/
*.log
private.key
```

这些目录不是源代码，可以在新电脑重新生成。微信上传密钥 `private.key` 属于敏感文件，只能单独通过安全方式传输，不要放进压缩包、网盘公共链接或 Git 仓库。

在原电脑制作源码压缩包，可进入项目上一级目录后执行：

```bash
zip -r travel-atlas-mini-source.zip travel-atlas-mini \
  -x 'travel-atlas-mini/node_modules/*' \
     'travel-atlas-mini/dist/*' \
     'travel-atlas-mini/dist-h5/*' \
     'travel-atlas-mini/artifacts/*' \
     'travel-atlas-mini/*.log'
```

也可以把项目放入私人 Git 仓库，在另一台电脑通过 `git clone` 获取。提交前必须确认没有 `private.key`、AppSecret、访问令牌或个人账号信息。

## 5. 新电脑环境准备

需要安装：

1. Node.js 和 npm；
2. 一个代码编辑器，例如 VS Code 或 Codex；
3. 若需要真机调试，可安装微信开发者工具；
4. 若工作电脑不能安装微信开发者工具，可使用项目自带的微信 CI 上传方式。

本项目已在以下本机环境完成构建：

```text
Node.js v25.9.0
npm 11.12.1
```

为了避免不同电脑依赖不一致，新电脑应保留并使用项目中的 `package-lock.json`，使用 `npm ci` 安装。

检查环境：

```bash
node -v
npm -v
```

## 6. 第一次启动

解压或克隆项目后，在终端进入项目目录：

```bash
cd travel-atlas-mini
npm ci
```

先检查代码：

```bash
npm run check
```

### 6.1 打开网页版本

构建 H5：

```bash
npm run build:h5
```

构建结果位于 `dist-h5/`。启动本地预览：

```bash
python3 -m http.server 4174 --directory dist-h5
```

浏览器打开：

```text
http://localhost:4174/#/pages/index/index
```

每次修改代码后，需要重新执行 `npm run build:h5`。需要自动监听修改时，可以使用：

```bash
npm run dev:h5
```

### 6.2 构建微信小程序

```bash
npm run build:weapp
```

构建结果位于 `dist/`。

如果安装了微信开发者工具，导入项目根目录中的 `project.config.json`。微信开发者工具会读取 `dist/` 作为小程序代码目录。

当前 `project.config.json` 使用演示 AppID：

```text
touristappid
```

正式联调前，需要替换为自己注册的小程序 AppID。不要使用他人的 AppID。

## 7. 不安装微信开发者工具的方式

项目已经集成 `miniprogram-ci`，可以通过命令行生成体验二维码或上传开发版本。

先复制环境变量示例：

```bash
cp .env.ci.example .env.ci
```

需要准备：

- 微信小程序 AppID；
- 微信公众平台下载的代码上传密钥；
- 微信公众平台允许当前电脑 IP 上传代码。

生成体验二维码：

```bash
WECHAT_APP_ID=wx你的AppID \
WECHAT_PRIVATE_KEY_PATH=/安全目录/private.key \
npm run ci:preview
```

二维码生成到：

```text
artifacts/preview.png
```

上传开发版本：

```bash
WECHAT_APP_ID=wx你的AppID \
WECHAT_PRIVATE_KEY_PATH=/安全目录/private.key \
MINI_VERSION=0.1.0 \
MINI_DESCRIPTION='旅图体验版本' \
npm run ci:upload
```

更详细说明见 `docs/NO_INSTALL_RELEASE.md`。

## 9. 当前数据如何保存

收藏、去过、行程和关注状态保存在本机：

```text
src/lib/storage.ts
```

主要存储键：

```text
lvtu-mini-want
lvtu-mini-been
lvtu-mini-trip
lvtu-mini-follow
```

清理浏览器缓存、删除小程序或换电脑后，这些数据可能消失。开发真实产品时，应把它们迁移到后端数据库，并与微信用户身份绑定。

## 10. 后续后端建议

建议下一阶段按以下边界建设：

```text

        ↓ HTTPS API

        ↓
```

首个可上线版本至少需要：

1. 微信登录和用户资料；
2. 景点、攻略、景评、旅圈、话题的数据表；
3. 图片上传与压缩；

5. 举报、删除和账号封禁能力；
6. 收藏、关注、回复和行程云端同步；
7. 管理后台；
8. 隐私政策、用户协议和小程序隐私指引。

## 11. 开发完成前的检查

每次准备交付或复制到另一台电脑前执行：

```bash
npm run check
npm run build:h5
npm run build:weapp
```

检查以下页面：

- 首页能进入景点和旅圈；
- 目的地搜索与筛选可用；
- 景点收藏、去过、加入行程可用；
- 行程页可以选择日期、修改时间和备注；
- 发布页可以切换内容类型；
- 个人中心能展示本地收藏和关注结果；
- 页面刷新后不存在空白页；
- 图片地址在 H5 和微信小程序中都能加载。

## 12. 常见问题

### 页面打不开或显示旧版本

重新构建并重启预览：

```bash
npm run build:h5
python3 -m http.server 4174 --directory dist-h5
```

浏览器使用强制刷新。若 4174 端口被占用，可以改用 4175：

```bash
python3 -m http.server 4175 --directory dist-h5
```

### 安装依赖失败

先确认终端位于 `travel-atlas-mini` 目录，并确认网络可以访问 npm。不要复制其他电脑的 `node_modules`，删除不完整的 `node_modules` 后重新执行 `npm ci`。

### H5 图片能显示，小程序图片不显示

确认图片已经放入 `public/places/`，重新执行 `npm run build:weapp`，并检查 `dist/places/` 是否存在对应文件。

### 微信上传失败

依次检查 AppID、上传密钥绝对路径、IP 白名单、开发者权限和版本号。上传密钥不能提交到代码仓库。
